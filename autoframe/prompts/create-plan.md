# PLAN.mdの作成・更新（ユーザーからの依頼用）

[SPEC.md](../SPEC.md)の§2に従い、指定されたプロジェクトのPLAN.mdを作成・更新する。これは自動実行中のWorker用プロンプトではない。

- 目的・対象・完成条件・制約を確認し、構成と既存の検証手順を調べる。未確認の資料・コマンドを確定事項として書かない。要求や変更範囲に関わる未解決の判断だけを質問する。
- 新規PLANのgenerated_scopeには `**/.vs/**`、`**/bin/**`、`**/obj/**`、`**/TestResults/**`、`**/BenchmarkDotNet.Artifacts/**` を必ず記載する。全プロジェクト共通の固定既定値で、IDE・言語・フォルダーの存在検出は条件にしない。既存PLANで未指定でもRunnerが適用するため、追記だけのために更新や判断を要求しない。その他の生成先は必要に応じて追加し、既存指定を保持する。.vscode・.ideaやNuGet.Configなど設定・ソース・指示ファイルを一括除外しない。.gitignoreは保護解除の根拠にしない。
- .NETではWorkerがcheck-dependencies.ps1を自分の環境で実行する。environment_checksはRunner環境の確認でありWorkerの権限を保証しない。tasksの実施・検証手順には、長時間作業前のrestore、設定アクセス拒否などの原因・解除条件の記録、影響する項目のblocked化を含める。ACLやNuGet設定・取得元の自動変更を復旧策にしない。
- PLAN.mdのJSONブロックの前に「ユーザープロンプト（原文）」を設け、ユーザーが入力した「目的」「対象」「完成条件」「対象外・制約」を要約・補完せず、原文のまま保存する。未入力の項目は未入力と記し、推測で埋めない。具体化した内容は実行用JSONへ記載し、保存前に原文との整合を確認する。依頼されていない原文の変更はしない。
- 目的と完成条件から、実施・検証可能なtasksと、到達条件付きのmilestonesを自動生成する。小規模なら1件、複数の意味のある節目があれば分ける。数を増やすことを目的にしない。
- 各マイルストーンにid、description、空でないtask_ids、確認可能なacceptanceを記す。全必須項目をいずれかのマイルストーンへ対応付ける。完成に必須の条件はcompletion_criteriaにも記す。
- 更新はRunner停止中に行い、依頼外の要件と安定したIDを保持する。ユーザーが要件を変更した場合は、明示された変更を原文とJSONへ整合して反映する。進捗・証拠・生成過程はPLAN.mdへ書かない。
- [PLAN.template.md](../templates/PLAN.template.md)と[plan.schema.json](../schemas/plan.schema.json)を使い、JSON、必須フィールド、一意ID、参照、依存の循環、完成条件とマイルストーンの網羅性を確認する。
- PLAN.mdだけを保存し、保存先と検査結果を簡潔に報告する。製品の修正・テスト・自動実行は開始しない。
